# 第1弾: 絵文字ローグ（CLIゲーム）

- **技術駆動／ルネッサンス的な意図**: Rogue系はASCIIという制約下での表現最適化から生まれた。絵文字は「等幅でないが意味を持つ記号」という点でASCIIの現代的後継と解釈できる。CLI×Unicode×TUIライブラリは「使えるが誰もやらない」実験領域であり、Webでやると凡庸になる
- 採用ライブラリ: **rot.js**（JS向けOSSローグライクライブラリ。マップ生成・FOV・パスファインディング・ターン制処理を提供）
- **カラー絵文字は必須**（白黒記号扱いにするとインパクトが無さすぎるため）。その代償として生じる技術的地雷への対処方針:
  - 論理セルと描画セルを完全分離する（1タイル=1意味の論理グリッドに対し、描画は1タイル=横2文字のセル幅で固定する。`TILE_W = 2` で `x * TILE_W` に描画を寄せる）
  - 絵文字幅の実行時計測（wcwidth等）は絵文字では信用できないため、設計で決め打ちする
  - 絵文字セットは「技術的に安定しているカテゴリ」（人物・モンスター・地形・アイテムの基本形）に厳選し、組み合わせ絵文字（ZWJ）・国旗・肌色修飾・最近追加された絵文字は避ける。判定基準の技術的根拠は `docs/emoji-policy.md` にまとめてある
  - Windows Terminal必須・推奨フォント明記など、環境依存であることをREADMEで明文化する（「表示崩れは既知の制約であり、バグとは限らない」という一文が必須）。これは技術的怠慢ではなく、旧来のローグが「フォント設定はユーザーに合わせさせる」文化を持っていたことの現代的踏襲

# コンセプト方針(2026-07-23決定)

- **「絵文字ローグ」という看板は、オリジナルRogueを絵文字でやる試みという具体的な約束として読まれる**(単なる「ローグライク」という緩いジャンル接尾辞ではなく、固有の作品名Rogueを直接冠しているため)。ルネッサンス的発想(ASCII→絵文字という表現手法の実験)自体は技術面の話であり、乗り物として選んだRogueのゲームデザインを離れて良い理由にはならない
- 方針: **オリジナルRogue(5.4系、`docs/rogue-5.4-spec.md`)への忠実さを優先**。不思議のダンジョンシリーズ(シレン等)由来の要素——本家に存在しない仕組み(クロンの風・モンスターハウス等)——は今後追加しない。既存実装済みのものも削除対象とする(クロンの風・モンスターハウスは`docs/tasks/game.md`マイルストーン106で削除済み)
- **絵文字都合のアレンジは許容**。該当する絵文字が存在しない/安定基準を満たさない場合の代替(例: yetiに対応する安定絵文字が無いため🐻(熊)で代替)は、本家の意図(モンスターの記号としての機能)を壊さない範囲でのアレンジとして許可する
- 開発者(ゆうやみ)自身はRogue世代ではなく不思議のダンジョンシリーズのプレイ経験しかないため、この方針は個人的な好みではなく看板が持つ対外的な約束を優先する判断であることを明記しておく
