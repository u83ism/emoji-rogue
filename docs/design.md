# 第1弾: 絵文字ローグ（CLIゲーム）

- **技術駆動／ルネッサンス的な意図**: Rogue系はASCIIという制約下での表現最適化から生まれた。絵文字は「等幅でないが意味を持つ記号」という点でASCIIの現代的後継と解釈できる。CLI×Unicode×TUIライブラリは「使えるが誰もやらない」実験領域であり、Webでやると凡庸になる
- 採用ライブラリ: **rot.js**（JS向けOSSローグライクライブラリ。マップ生成・FOV・パスファインディング・ターン制処理を提供）
- **カラー絵文字は必須**（白黒記号扱いにするとインパクトが無さすぎるため）。その代償として生じる技術的地雷への対処方針:
  - 論理セルと描画セルを完全分離する（1タイル=1意味の論理グリッドに対し、描画は1タイル=横2文字のセル幅で固定する。`TILE_W = 2` で `x * TILE_W` に描画を寄せる）
  - 絵文字幅の実行時計測（wcwidth等）は絵文字では信用できないため、設計で決め打ちする
  - 絵文字セットは「技術的に安定しているカテゴリ」（人物・モンスター・地形・アイテムの基本形）に厳選し、組み合わせ絵文字（ZWJ）・国旗・肌色修飾・最近追加された絵文字は避ける。判定基準の技術的根拠は `docs/emoji-policy.md` にまとめてある
  - Windows Terminal必須・推奨フォント明記など、環境依存であることをREADMEで明文化する（「表示崩れは既知の制約であり、バグとは限らない」という一文が必須）。これは技術的怠慢ではなく、旧来のローグが「フォント設定はユーザーに合わせさせる」文化を持っていたことの現代的踏襲

# コンセプト方針(2026-07-23決定)

- **「絵文字ローグ」という看板は、オリジナルRogueを絵文字でやる試みという具体的な約束として読まれる**(単なる「ローグライク」という緩いジャンル接尾辞ではなく、固有の作品名Rogueを直接冠しているため)。ルネッサンス的発想(ASCII→絵文字という表現手法の実験)自体は技術面の話であり、乗り物として選んだRogueのゲームデザインを離れて良い理由にはならない
- 方針: **オリジナルRogue(5.4系、`docs/rogue-5.4-spec.md`)への忠実さを優先**。不思議のダンジョンシリーズ(シレン等)由来の要素——本家に存在しない仕組み(クロンの風・モンスターハウス等)——は今後追加しない。既存実装済みのものも削除対象とする(クロンの風・モンスターハウスは`docs/tasks/game.md`マイルストーン106で削除済み)
- **絵文字の割り当ては「まず本家ありき」**(2026-11-20本人訂正)。名前も能力も本家5.4のものが出発点で、そこに絵文字を当てる。当て方で3通りに分かれる:
  1. **本家のものをそのまま表せる絵文字があり、他で使っていない** → その絵文字で、名前も本家のまま
  2. **ぴったりの絵文字が無い**(ファンタジー色の強いモンスター等) → 安定基準(`docs/emoji-policy.md`)を満たす絵文字に無理やり当て込み、**名前はその絵文字に合わせて変えざるを得なければ変える。能力・数値は本家のまま**(例: yetiに対応する安定絵文字が無いため🐻で代替し「雪男」)
  3. **絵文字はあるが別の用途で使っている/1つの絵文字に複数の意味を背負わせることになる** → 使ってよいかは**UIの問題なので、実際の画面を見て人間が判断する**(例: 「戦う」「攻撃力」「武器」「剣」を全部⚔️で表してよいか)。AIは候補と懸念を出すところまでで、決めない
  - **本家のアルファベット(A〜Z)は合わせる対象ではない**(2026-11-20本人指摘)。当時のCLIで1文字の空間に敵を見分けるための表示記号にすぎず、emoji-rogueの絵文字がその役目の現代版にあたる。割り当ては「本家のどのモンスターか」という中身で考え、「Rの枠に何を入れるか」のように文字の枠で考えない
  - 2と3の判断は一度で終わらず、絵文字ごとの地味な調整を続けていく作業になる(画面を見て決めるものは`docs/tasks/game.md`の「判断待ち」、これまでの検討の経緯は`docs/tasks/game-notes.md`の「本家ありきの絵文字割り当て見直し」)
  - 間違えやすい点: 「今の名前と絵文字を残し、能力だけ本家に合わせる」も「本家の名前に戻し、絵文字を選び直す」も、上の手順を飛ばしているので既定にしない(2026-11-20、どちらも提案して本人に「ズレがある」「まだ違う」と指摘された)
- **建て付けは「Rogue 5.4の現代化」(2026-11-20本人明言)**。現代化するのは**見た目(絵文字の描画・UI・操作感)と中のコード(関数型TypeScriptでの書き直し・セーブ/リプレイ・テスト)**であって、**ゲームのルールとバランスはあえて本家のまま変えない**。したがって:
  - 本家と挙動・数値が違う箇所は、見つけしだい**本家に合わせるのが既定**。「アレンジとして残すか」を本人に判断を仰ぐ論点にしない(2026-11-19、敵4種の名前と能力を本家に合わせるかを「決めていただきたいこと」として挙げ、本人から「判断できない時点で問題」と指摘された)
  - 本家に無い要素(シレン由来に限らず、Brogue由来の生命の薬・出どころ不明の杖のstrikingなども)は削除・本家の要素への置き換えの対象
  - BOTの成績が悪くても数値は調整しない。手応えの改善はBOTの賢さとUI・操作感の側で行う
  - 例外は2つだけ: ①上の「まず本家ありき」の手順2・3で、絵文字に合わせて名前・見た目を変えるもの ②本人が個別に決めたもの(盗賊の名前を「盗賊」のまま残す、2026-11-12。名前だけで挙動は本家どおり)。本家の仕組みが端末UIでは再現しにくい場合(例: 投げる方向の選択)は、UI側の工夫で本家の挙動に近づける
  - 本家の仕様がソースで確認できない点は、推測で埋めずに`lcn2/rogue5.4`のソースを読んで確かめる(`docs/rogue-5.4-spec.md`冒頭を参照)
- 開発者(ゆうやみ)自身はRogue世代ではなく不思議のダンジョンシリーズのプレイ経験しかないため、この方針は個人的な好みではなく看板が持つ対外的な約束を優先する判断であることを明記しておく
